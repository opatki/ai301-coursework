# Rubric: is this plan ready to post and build from?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diagnosis-grounded | The plan's stated cause (its Diagnosis section) read against the repro-evidence block's steps, controls, and artifacts | The stated cause explains every control and outcome the repro evidence shows: a control that ran clean is accounted for by the cause (it's outside the triggering condition), and the failing case is exactly what the cause predicts. Fails when any control, artifact, or evidence line contradicts or is left unexplained by the stated cause, or when the diagnosis does not engage the repro evidence at all (asserts a cause without tying it to what the evidence showed) | required |
| bounded-scope | The plan's Scope statement and its Approach/Files-to-touch, read against the issue's reported symptom | The change is one bounded fix addressing the issue as reported; anything beyond the immediate fix (a refactor, a migration, a new feature, a redesign, "while I'm in the area" work) is either absent or explicitly named as deferred/not-in-scope rather than folded into the change. Fails when the plan bundles unrelated or broader work into the change itself, even if the core fix inside it is correct | required |
| executable | The plan's Approach and Files-to-touch, read for whether a stranger could start work without asking the author anything | The plan names a concrete location (file, module, or subsystem) and a decided mechanism for the fix — what will change and how. A stranger could open that location and start applying the mechanism. This still passes when the exact function/line is left to be pinned down during implementation, as long as the location and mechanism are both decided and the plan states how the exact spot gets found (e.g., "traced with debug logs, which I have working"). Fails when the approach itself is undecided — which of several strategies to take, which layer or fork to fix, a choice deferred to "whichever is easier" or "not sure yet" — or when no location/mechanism is named at all | required |
| decisive-test-plan | The plan's Test plan section, read against the repro-evidence block's own steps and artifacts | The test plan names an observable outcome specific to the fix: re-running the repro's exact (or equivalent) steps with a stated expected result (an exit code, printed output, a passing assertion), or a named regression test tied to the issue. Fails when the test plan is generic and names no outcome tied to the fix itself ("run the full test suite," "should feel fast," "nothing else should feel broken") | required |
| thread-aware-comms | The candidate plan comment, read against the Thread highlights block (for direction a maintainer already gave) and the Repo facts block's contribution/AI policy (for disclosure requirements) | Both must hold: (1) if a maintainer's thread comment already pointed at a cause, a file, or an approach, the plan comment explicitly engages it — follows it, or states a reasoned reason for diverging — rather than silently proposing something else; (2) if the repo's stated contribution policy requires disclosing AI assistance (on issue comments, or on contributions generally with no comment-specific carve-out), the plan comment discloses it. In eval mode, treat every candidate plan comment as AI-assisted work for part (2), since no package states otherwise. Fails if either applicable condition is not met. Neither sub-condition applies (and the check passes) when the thread contains no maintainer direction and the repo's policy states no disclosure is required for comments | required |

## Verdict rule

Accept (ready) only if all five required checks pass. Any required check that fails holds the package at reject. There are no preferred checks this round; every check above gates the verdict directly. A check graded `unclear` — meaning the procedure could not find enough in the package to decide pass or fail — is treated as a fail: a plan whose evidence doesn't let you confirm a check is not a plan that's ready to post and build from.
